# ЯЗЫК КАМЕРЫ MYDRIASIS

Это самый важный технический документ проекта. Камера здесь — не инструмент
игрока, а автор: она решает, что игрок видит и, главное, **откуда**.

Референс: **Buckshot Roulette**. Механика языка — статика, резкая склейка,
взгляд со стороны, невозможность контролировать точку зрения, микро-движение
внутри кадра.

---

## 1. Семь правил

1. **Камера не вращается мышью.** Никогда. Мышью поворачивается только голова
   героя, и то в конусе. Игрок управляет телом, а не взглядом.
2. **Склейка, а не переезд.** Смена ракурса — мгновенная. Единственные плавные
   движения — микро-наезд и сценарные доли.
3. **Внутри кадра камера жива.** Дрейф «живой руки», дыхание, саккады, толчок
   от удара сердца, тряска от событий.
4. **Композиция важнее удобства.** Герой стоит в трети кадра. Передний план
   всегда чем-то перекрыт.
5. **Камера стоит в помещении.** Никаких орбит, никаких «сверху на весь блок».
6. **Ракурс выбирается данными, а не скриптом.** Список ракурсов — JSON;
   режиссёр сам выбирает подходящий по дистанции, тегам и доле.
7. **То, чего игрок не видит, живёт своей жизнью.** При склейке предметы
   могут менять положение за кадром (см. §6).

---

## 2. Управление головой

| Параметр | Значение |
|---|---|
| Предел поворота головы по горизонтали | ±1.25 рад (±72°) |
| По вертикали | −0.85 … +0.75 рад (−49° … +43°) |
| Чувствительность по умолчанию | 0.0022 (настраивается) |
| Сглаживание | плавание ±0.006 рад — голова не держится идеально ровно |
| Тремор | от `GameState.tremor()`: до ±0.01 рад при пульсе 180 |

Взаимодействие идёт **лучом из головы**, а не из центра кадра. Поэтому HUD
показывает риску направления головы: при жёстких склейках без неё игрок
теряет связь между «куда я смотрю» и «куда смотрит кадр».

## 3. Жизнь внутри кадра

Всё считается в `CameraDirector._place_camera()`:

| Слой | Амплитуда | Источник |
|---|---|---|
| Дрейф «живой руки» | до 6 см, 3 независимых шума (Simplex, 0.12 Гц) | параметр `handheld` ракурса |
| Дыхание | ±1.2 см | фаза дыхания героя |
| Удар сердца | до 1.2 см по оси взгляда | конверт удара × (пульс−70)/110 |
| Тремор | до 4 мм | `GameState.tremor()` |
| Саккады | 0.2–0.4° раз в 1.5–4 с | собственный таймер |
| Тряска от событий | затухание 2.6/с | `director.impact(amount)` |
| Наезд (dolly) | до 1.4 м | `push_in × (0.4 + 1.8 × напряжение)` |
| FOV | ±0.18° дыхание, +0.35° удар | виталитеты |
| Крен | 0–2.4° | параметр `roll` ракурса |

Демпфирование позиции — 14/с: этого достаточно, чтобы саккада читалась как
рывок, а не как переезд, но склейка всё равно мгновенная (позиция ставится
жёстко при смене ракурса).

## 4. Как выбирается ракурс

Каждый ракурс — ресурс `CameraFrame` (`scripts/camera/camera_frame.gd`) со
своими полями. Раз в 0.35 с режиссёр пересчитывает оценки:

```
score = distance_score(дистанция)
      + bias
      + 0.75 × (число совпавших тегов интереса)
      + 0.22, если ракурс уже стоит (инерция)
      − штраф, если склейка была меньше секунды назад
```

Ракурс считается **недоступным**, если игрок вне его дистанций
(`min_distance … max_distance`), а ракурсы с `scripted_only` берутся только по
прямой команде.

Склейка происходит, когда:

* игрок вышел из рабочей дистанции текущего ракурса (`reason = "range"`);
* истекла доля ракурса (`reason = "dwell"`, 2.2–7 с, случайно в диапазоне);
* ракурс-претендент уверенно выигрывает;
* сцена потребовала конкретный кадр (`reason = "scripted"`).

`distance_score` не линейна: оптимум — **первая треть** диапазона. Камера любит
стоять близко и смотреть снизу или с плеча.

## 5. Формат ракурса

Файлы: `resources/camera_frames/*.json`. Пример (открывающий кадр бита):

```json
{
  "id": "opening_floor",
  "position": [0.78, 0.34, -6.66],
  "target_offset": [0.0, 0.30, 0.0],
  "fov": 44.0,
  "bias": 2.0,
  "tags": ["start"],
  "min_distance": 0.0,
  "max_distance": 3.2,
  "dwell_min": 5.0, "dwell_max": 7.0,
  "handheld": 0.65,
  "push_in": 0.02,
  "roll": -1.6,
  "composition_offset": -0.35,
  "opening": true
}
```

| Поле | Смысл |
|---|---|
| `position` | точка камеры в мире; при `fixed_in_world: false` — смещение от головы героя |
| `target_offset` | куда смотреть относительно головы героя |
| `fov` | 26–54°: у длинных кадров меньше, у «в лицо» больше |
| `bias` | приоритет; повышайте для кадров, которые обязаны случаться |
| `tags` | совпадают с тегами интереса уровня (`ward`, `mirror`, `station`…) |
| `dwell_min/max` | доля кадра в секундах |
| `handheld` | 0 — штатив, 1 — камера в чужих руках |
| `push_in` | м/с медленного наезда при росте ужаса |
| `roll` | крен, градусы (использовать скупо: ±2.5 максимум) |
| `composition_offset` | −1 герой в левой трети, +1 — в правой |
| `height_bias` | вертикальное смещение точки взгляда |
| `opening` | кадр, с которого начинается бит |
| `scripted_only` | только по прямой команде сцены |

### Как ставить кадры

1. Идите по блокингу и ставьте камеру туда, где стоит человек, а не туда, откуда
   «удобно смотреть».
2. Перекрывайте передний план: косяк, край каталки, штатив.
3. Дайте герою уйти в треть кадра.
4. Диапазон дистанции — не шире трёх метров, иначе игрок будет гулять по
   «мёртвой зоне».
5. Держите 3–5 кадров на комнату: один широкий, два средних, один низкий,
   один «в лицо».

## 6. Триггеры и склейки по событию

* `CameraTrigger` (`scripts/camera/camera_trigger.gd`) — зона, которая
  навязывает ракурс на N секунд. Используется на входах в помещения и в
  кульминациях.
* `CameraDirector.cut_to(id, hold, reason)` — прямая склейка из сценария;
  `release_scripted()` возвращает управление режиссёру; `lock(true)` замораживает
  камеру совсем (финал: асистолия).
* `set_interest_tags([...])` — уровень объявляет, что сейчас важно: режиссёр
  начинает предпочитать ракурсы с этими тегами.

### Приём «перенос, пока не смотрят»

`ward_level.gd` держит список `_shifters`: объекты с несколькими точками
положения. На каждой склейке режиссёр проверяет, попадает ли объект в пирамиду
видимости текущего кадра (`Camera3D.is_position_in_frustum`) и не слишком ли он
близко к игроку. Если объект не виден — он **переносится в следующую точку**,
с тихим металлическим отзвуком.

Игрок никогда не видит движение. Он видит расхождение между кадрами: коляска
стояла у койки, а через минуту — у окна. Это основной источник тихого ужаса в
бите, и он принципиально отличается от скримера: никто не прыгает на игрока,
мир просто не совпадает сам с собой.

## 7. Отладка

| Клавиша | Что делает |
|---|---|
| `F1` | отладочная свободная камера (переключение) |
| `F2` | следующий ракурс по списку (проверка композиции) |
| `F10` | циклическая смена уровня качества на ходу |

`F2` — главный инструмент: пролистать все ракурсы подряд и убедиться, что в
каждом есть композиция, перекрытие переднего плана и ни одного «пустого» кадра.
